the previously selected encrypted local enrollment, with exact selected-device

was issued.

- Status request succeeded and returned the fixed normalized projection:
  reachability, bounded battery percentage, robot/task/station state and paused
  flag. No raw device/account IDs were returned.
- Read-only details succeeded: 11 supported queries reached the robot, producing
  ten normalized setting fields and 14 maintenance service-counter entries.
  Only scalar/enum settings and counter classifications passed the projection.
- No maps, room names, room geometry, camera streams, logs or vendor response
  objects were requested or included in evidence.
- SDK version 18.7.0 was enforced and its HTTP retry count was one. Selection
  stayed bound to the original local enrollment.

## Automated safety checks

JavaScript tests cover projection/privacy, fixed action/empty-argument policy,
authorization after cloud preflight, no replay after dispatch timeout, station
service versus completion, normalized service counters, shared serialization,
fixed subprocess arguments/no shell, malformed output and bounded output.
The worker receives only a fixed environment allowlist, excluding unrelated
credentials, proxy configuration, Python injection variables and TLS overrides.

Pure Python tests cover exact selected-device binding with no fallback, request
field/action allowlists, state preflight, acceptance/state distinctions, the SDK
retry guard, and a simulated HTTP 502 producing exactly one SDK POST. These tests
make no network or hardware requests.

normalized state through `HubClient.state`. The returned field was fresh
(`stale: false`), with source `ecovacs-cloud-https`. No runtime state values are
included here.

A separate scoped client was tested through the hub API:

- Read-only state returned fresh data.
- The advertised action list contained only `vacuum.details.read`.
- `vacuum.details.read` was confirmed with 11 successful queries, ten normalized
  setting fields and 14 maintenance counter entries.

No
